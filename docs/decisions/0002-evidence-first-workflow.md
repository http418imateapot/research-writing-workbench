# ADR 0002：採用 CTCC 工程研究控制環

狀態：Accepted

## 情境

本專案需要區分軟體已建置、行為已觀察、方案可比較、機制可解釋與結果可轉用。只靠論文章節或文字流程無法保存非同步完成語意、執行軌跡、故障反例與版本範圍。

## 決策

採用「契約—軌跡—反例—主張」（CTCC）控制環。契約定義可觀察行為；軌跡保存可重建執行；反例挑戰預期解釋；主張依實際證據由研究者裁定保留、縮小、重做或撤回。

## 後果

工程產物必須有版本、執行與位置；尚未執行的設計保持 `planned`。比較缺少共同契約、軌跡不能重建或反例未處理時，不能提升主張種類。此結構增加記錄成本，但使工程事實與研究陳述間的斷裂可被檢查。
