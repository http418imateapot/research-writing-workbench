# 軌跡、重現與證據包

## 執行前配置

為每個 scenario ID 定義需要保留的程式版本、設定、資料版本、命令、環境、時間來源、關聯識別碼、觀測點與預期斷言。沒有觀測設計的成功執行，可能無法回答研究問題。

## 執行紀錄

每次執行產生 execution ID，記錄實際命令、開始與結束時間、exit code、環境摘要、輸入、輸出位置、失敗及偏離契約之處。不得覆蓋原始輸出或只保存整理後摘要。

成熟度定義：

- `planned`：只有設計或待辦，尚未取得產物。
- `captured`：已保存實際產物，但尚未重現。
- `reproduced`：依記錄重新執行並得到契約允許的相符結果。
- `reviewed`：已檢查來源、完整性、反例與主張用途。
- `invalidated`：產物損壞、來源不明、不可重建或被反證，不再用於支持主張。

## 證據包內容

使用 [trace-index.md](../assets/templates/trace-index.md) 建立索引，不把大型原始 Log 複製進論文：

- repository、commit 或內容雜湊。
- 測試名稱、命令、exit code 與原始輸出。
- Trace/Log 檔、事件範圍與關聯 ID。
- 設定、資料及環境版本。
- 對應契約條款、scenario ID 與 execution ID。
- 已知缺段、時間偏差、取樣或清理規則。

觀察與原因推論必須分開。Diff 顯示發生變更；若要說變更造成結果，還需要排除其他同時變動與競爭解釋。
